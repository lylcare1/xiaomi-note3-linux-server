# Xiaomi Mi Note 3 (jason) Linux 服务器使用文档

> 废旧手机改造的无头 Linux 服务器，开机即用，零成本、低功耗。

## 快速开始

```bash
ssh user@172.16.42.1             # USB 连接，密码 DEVICE_PASS_PLACEHOLDER
sudo reboot                      # 重启
cat /var/log/battery-care.log | tail    # 电池状态
systemctl list-timers --all      # 监控任务一览
```

连接方式见 §1，运维操作见 §4，性能对比见 §7。

## 2. 连接方式

### USB NCM（首选，开机即用）

用数据线连接手机与电脑，开机后自动枚举 USB NCM 网卡。

```bash
ssh user@172.16.42.1        # 密码: DEVICE_PASS_PLACEHOLDER
```

- IP: `172.16.42.1/16`
- 用户: `user` (密码 `DEVICE_PASS_PLACEHOLDER`)
- root: `sudo -S` (用 user 密码)

### WiFi（局域网）

开机后 NetworkManager 自动连接已保存的 WiFi。

```bash
ssh user@192.168.66.165     # 当前 IP (DHCP 分配)
```

- SSID: `Green Tree Inn` (当前)
- IP 由 DHCP 分配，可能变化
- 查看当前 IP: `ssh user@172.16.42.1 'ip -4 addr show wlan0'`

### 添加新 WiFi

```bash
ssh user@172.16.42.1
sudo nmcli device wifi connect "<SSID>" password "<PASSWORD>" ifname wlan0
# 连接会自动保存，开机自动连接
```

## 4. 常用运维操作

### 重启 / 关机

```bash
# 远程重启 (可靠)
sshpass -p 'DEVICE_PASS_PLACEHOLDER' ssh user@172.16.42.1 'echo DEVICE_PASS_PLACEHOLDER | sudo -S reboot'

# 设备上直接重启
sudo reboot

# 切换到 fastboot (维护用)
sudo reboot bootloader
# 或关机后按住 音量下 + 电源
```

**重新开机**: 关机后按电源键, 设备自动进入 Linux (boot 已持久化, 无需 fastboot)。

**⚠️ 关于关机 (软件 poweroff 不可靠, 用 safe-poweroff.sh)**:

`sudo poweroff` 在本设备上**不可靠** — 内核 `pm_power_off` 未注册 (msm-restart 驱动只注册了 restart) + PSCI 固件 bug (`failed to set PC mode: -3`) 导致内核无法断电, softdog watchdog 30s 超时触发重启。

**正确的关机方法** (使用 safe-poweroff.sh):
```bash
# 1. 远程执行 safe-poweroff.sh (会让设备 halt 且不再重启)
sshpass -p 'DEVICE_PASS_PLACEHOLDER' ssh user@172.16.42.1 'echo DEVICE_PASS_PLACEHOLDER | sudo -S /usr/local/bin/safe-poweroff.sh'
# 2. 等设备 halt (SSH 断开, ping 不通, 但 USB 设备仍枚举)
# 3. 长按电源键 15 秒物理断电 (或拔 USB 线)
```

safe-poweroff.sh 原理: 禁用 systemd runtime watchdog → `halt -f` (强制 halt) → 设备进入 halt 状态, 不再被 softdog 重启。虽然 magic close 因 systemd 持有 /dev/watchdog0 报 Resource busy, 但 halt 后 softdog 的 hrtimer 不再触发 (CPU 进入 WFI), 设备稳定 halt。

**验证**: halt 后 90+ 秒设备未重启 (USB Dev 编号不变), 远超 softdog 30s 超时。

### 蓝牙

WCN3990 (UART), bluez 5.86。**默认关闭**（服务器场景，按需启用）。

```bash
sudo systemctl start bluetooth       # 启用
sudo systemctl stop bluetooth        # 关闭
systemctl is-active bluetooth        # 状态
hciconfig -a hci0                    # UP RUNNING = 正常
```

设备名 `Xiaomi Mi Note 3`，BD Address `02:00:9E:01:40:30`。支持 BLE/BR-EDR/GATT。

### 电池保养

设备作为长期服务器，电池长期 100% 容易鼓包。内核不支持软件充电阈值，只能**物理管理 + 软件监控**。

```bash
cat /var/log/battery-care.log | tail -5          # 查看监控日志
cat /run/battery-care.alert 2>/dev/null          # 查看告警
cat /sys/class/power_supply/qcom-battery/uevent  # 实时电池信息
```

**告警规则**: health!=Good(CRITICAL 换电池) / temp≥55°C(CRITICAL) / temp≥45°C(WARN) / capacity≥95%持续24h(WARN 拔USB放电) / capacity<20%(WARN 充电)。

**物理保养**: 每周拔 USB 放电到 30-50% 再充到 80-90%；每月完整充放电 1 次；保持通风，环境 <35°C。

### Watchdog 自动恢复

设备已启用内核 + systemd 双层 watchdog, 挂起/panic 后自动重启:

- **softdog 内核驱动**: /dev/watchdog0, 30s 超时
- **systemd RuntimeWatchdogSec=30**: PID1 每 15s 喂狗, 30s 无喂狗→内核重启
- **kernel.panic=120**: panic 后 120s 自动重启
- **kernel.panic_on_oops=1**: oops 触发 panic

```bash
# 查看 watchdog 状态
cat /sys/class/watchdog/watchdog0/identity    # Software Watchdog
cat /sys/class/watchdog/watchdog0/timeout     # 30
cat /sys/class/watchdog/watchdog0/state       # active

# 查看 systemd watchdog 配置
journalctl -b | grep -i "watchdog" | head -3
# 应看到: Watchdog running with a hardware timeout of 30s

# 查看 sysctl
sysctl kernel.panic kernel.panic_on_oops
```

触发条件: systemd 挂起 (D-state 等待) / 内核 oops / 内核 panic / 严重内存耗尽。

### 监控体系

设备已内置 9 个 systemd timer，自动监控运行状态：

| timer | 频率 | 用途 |
|-------|------|------|
| health-check | 5min | sshd/NM/wifi/网关健康，3 次失败自动 reboot |
| temp-monitor | 5min | 12 个 thermal zone，70°C 警告 / 85°C 关键 |
| net-monitor | 5min | wlan0/网关/外网连通性 + DNS |
| disk-io-monitor | 10min | mmcblk1 I/O 统计 |
| fake-rtc-save | 30min | 持久化系统时钟 (PMIC RTC 不可写) |
| battery-care | 1h | 电池健康/温度/电量告警 |
| apk-update-check | 24h | 软件包更新通知 |
| fsck-check | 7d | 只读 e2fsck 检查 rootfs |
| config-backup | 7d | 25 个关键配置备份到 /var/backups |

```bash
systemctl list-timers --all                    # 全部 timer
journalctl -u temp-monitor -n 20               # 某个 timer 日志
```

## 5. 部署 / 重刷流程

### 一键部署（主机侧）

部署脚本: [scripts/deploy.sh](../scripts/deploy.sh)

```bash
# 完整部署 (设备需在 fastboot)
./scripts/deploy.sh --all              # update-uuid + flash-rootfs + boot-temp + verify

# 持久化 boot 分区 (设备需已启动且 SSH 可达)
./scripts/deploy.sh --persist          # flash-boot (dd) + verify

# 单独步骤
./scripts/deploy.sh --update-uuid      # 从 rootfs 镜像更新 boot.img UUID
./scripts/deploy.sh --flash-rootfs     # fastboot flash userdata
./scripts/deploy.sh --boot-temp        # fastboot boot (临时)
./scripts/deploy.sh --flash-boot       # dd 写入 boot 分区 (持久化)
./scripts/deploy.sh --verify           # 验证 SSH + cpufreq
```

### 更新内核流程

1. 在 pmaports 中修改内核补丁
2. `pmbootstrap build linux-xiaomi-jason`
3. `pmbootstrap install`
4. `pmbootstrap export`
5. `./scripts/deploy.sh --all` (设备进 fastboot)
6. `./scripts/deploy.sh --persist` (设备启动后持久化)

### 刷回原厂

详见 [docs/刷机指南.md](./刷机指南.md)。原厂包在 `jason_images_V8.5.9.0.NCHCNED_20170831.0000.00_7.1_cn/`。

## 6. 启动流程

```
按电源键
  → bootloader 从 boot 分区加载 r32 内核
    → 内核启动 (cmdline: net.ifnames=0 cpuidle.off=1 consoleblank=60)
      → initramfs (USB NCM 网卡枚举 + losetup userdata)
        → switch_root → rootfs systemd
          → sshd + NetworkManager + WiFi 自动连接
            → SSH 可用 (约 60-90s)
```

无需任何手动干预，开机即 Linux。

## 7. 性能参考

对比 2 核 Intel Xeon Platinum 云服务器 (116.62.69.18, Ubuntu 5.15)，sysbench 1.0.20 / openssl 3.x，2026-07-02 实测:

| 测试 | Xiaomi Note 3 (8 核 ARM A53/A73) | 云服务器 (2 核 x86 Xeon) | 比值 |
|------|----------------------------------|--------------------------|------|
| CPU 单核 sysbench | 220.5 eps | 417.7 eps | 1:1.9 |
| CPU 多核 sysbench (8T / 2T) | 1324.6 eps | 655.7 eps | **2.0x** |
| 内存带宽 (write) | 3198 MiB/s | 7954 MiB/s | 1:2.5 |
| 磁盘随机读 IOPS | 29195 | 3056 | **9.6x** |
| 磁盘随机写 IOPS | 19463 | 2037 | **9.6x** |
| 磁盘顺序写 | 580 MiB/s | 163 MiB/s | **3.6x** |
| AES-256-CBC (8K, 硬件加速) | 332 MB/s | 846 MB/s | 1:2.5 |
| SHA256 (8K) | 288 MB/s | 389 MB/s | 1:1.35 |
| 网络延迟 → 8.8.8.8 | 232 ms | 242 ms | 相当 |
| 手机 ↔ 云服务器延迟 | 50 ms | 50 ms | - |
| 主机 → 手机 USB NCM | 1.9 ms / 279 Mbps | - (公网) | - |

**结论**:
- 手机 **多核总吞吐** 是云服务器 2 倍（8 核 vs 2 核优势）
- 手机 **磁盘 IOPS** 是云服务器 9.6 倍（eMMC vs 普通云盘，数据库/缓存场景优势显著）
- 单核性能、内存带宽、AES 加密约为云服务器 40%（典型 ARM vs x86 差距）
- 网络延迟相当，手机 ↔ 云同地区仅 50ms

**适用场景**: 轻量常驻服务（SSH 跳板、监控、MQTT、轻量 Web、cron）、IOPS 敏感型小负载（SQLite、Redis）、低并发、功耗敏感。
**不适用**: 单核 CPU 密集计算、高并发内存带宽敏感应用、大流量公网服务。

## 8. 注意事项

- **boot 分区持久化**: 用 `dd` 写入 (非 `fastboot flash boot`)，详见 [scripts/deploy.sh](../scripts/deploy.sh) `--flash-boot`
- **UUID 同步**: 每次 `pmbootstrap install` 后 rootfs UUID 会变，必须用 `--update-uuid` 更新 boot.img cmdline
- **cpuidle.off=1**: 内核 cmdline 参数，禁用 cpuidle 避免已知死锁
- **WiFi firmware**: 设备 modem 分区刷入 whyred NON-HLOS.bin (fw 1.0.0.591)，详见 [docs/故障排查.md](./故障排查.md) §7.4
- **回退路径**: 原厂备份在 `backups/original-jason-20260627-114354/`，原厂 fastboot 包可随时刷回
- **温度**: 空闲 40-43°C，长期高负载建议外接散热
- **DNS**: 若 `apk` 报 "DNS: transient error"，检查 `/etc/resolv.conf`，本地 DNS 服务 (127.0.0.1) 可能 REFUSED，临时改为 `nameserver 8.8.8.8`
