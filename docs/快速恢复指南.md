## 2. bootloop 应急（health-check 导致，最常见）

**典型场景**: 设备放背包/弱信号环境, health-check 检测 wlan0 down, 3 次失败 (15min) reboot, 循环。

### 2.1 进 fastboot 停止循环

```bash
# 方法 A: 设备开机时 (若 SSH 还能连一下)
ssh user@172.16.42.1 'echo DEVICE_PASS_PLACEHOLDER | sudo -S reboot bootloader'

# 方法 B: 关机后按住 音量下 + 电源
# 方法 C: 若能进 TWRP, adb reboot bootloader
```

### 2.2 用 deploy.sh 一键恢复 (会丢失设备配置)

```bash
cd /home/lyl/Documents/system/XiaoMiNote3
# 确认 pmbootstrap export 已完成 (boot.img + xiaomi-jason.img 在 /tmp/postmarketOS-export/)
./scripts/deploy.sh --all      # update-uuid + flash-rootfs + boot-temp + verify
# 等 60-90s 后 SSH 可达
./scripts/deploy.sh --persist  # 持久化 boot 到 boot 分区 (dd)
```

### 2.3 不重刷 rootfs, 只停 health-check (保留配置)

```bash
# 设备启动后 (即使 bootloop, 在 reboot 间隙的 SSH 窗口也能操作)
ssh user@172.16.42.1 'echo DEVICE_PASS_PLACEHOLDER | sudo -S systemctl stop health-check.timer'
ssh user@172.16.42.1 'echo DEVICE_PASS_PLACEHOLDER | sudo -S systemctl disable health-check.timer'
# 然后修 health-check.sh (见 §6 部署 r3 版本)
```

**注**: r3 版 health-check 已区分软/硬故障, WiFi 弱信号不再快速 reboot, 且 WiFi radio 关闭时跳过检查。若已是 r3 仍 bootloop, 排查其他原因 (ath10k crash / 服务崩溃)。

## 3. boot 分区修复

```bash
# 当前 boot 是 pmOS initramfs→systemd boot (jason-boot-initramfs.img 或 deploy.sh 生成的 boot.img)
fastboot flash boot /tmp/postmarketOS-export/boot.img
fastboot reboot

# 回退原厂 boot (会回到 Android, 最后手段)
cd jason_images_V8.5.9.0.NCHCNED_20170831.0000.00_7.1_cn
echo HOST_SUDO_PASS_PLACEHOLDER | sudo -S fastboot flash boot boot.img
echo HOST_SUDO_PASS_PLACEHOLDER | sudo -S fastboot reboot
```

**注意**: 切勿混淆 pmOS boot 和原厂 boot。当前设备 boot 分区是 pmOS boot (含 r32 内核 + initramfs)。

## 4. SSH/USB NCM 排查

设备 IP: `172.16.42.1` (USB NCM), 用户: `user`, 密码: `DEVICE_PASS_PLACEHOLDER`

```bash
# 1. 主机看 USB 设备是否枚举
lsusb -t | grep cdc_ncm       # 应看到 cdc_ncm 驱动绑定

# 2. 主机网络接口 (接口名每次 reboot 可能变, 因 MAC 变化)
ip addr show | grep "inet 172.16.42"    # 主机侧 IP, 通常 .2 或 .253

# 3. ping 测试
ping -c 2 172.16.42.1

# 4. SSH (首次连接需清 known_hosts, 因 rootfs 重刷后 host key 变)
ssh-keygen -f "/home/lyl/.ssh/known_hosts" -R "172.16.42.1"
sshpass -p 'DEVICE_PASS_PLACEHOLDER' ssh -o StrictHostKeyChecking=no user@172.16.42.1

# 5. 若 ping 通但 SSH refused: 首次启动 sshd 慢, 等 60s
# 6. 若 USB 完全不枚举: boot.img 损坏, 进 fastboot 重刷 (§3)
```

## 5. WiFi 配置恢复 (NetworkManager 模式)

```bash
ssh user@172.16.42.1
# 扫描
sudo nmcli device wifi rescan
nmcli device wifi list | head -10

# 连接 (SSID 有空格用引号)
sudo nmcli device wifi connect "Green Tree Inn" password "4006998998" ifname wlan0
# 或用 connection add (避免 connect 命令的引号嵌套问题)
sudo nmcli connection add type wifi ifname wlan0 con-name GreenTree ssid "Green Tree Inn" \
    wifi-sec.key-mgmt wpa-psk wifi-sec.psk 4006998998
sudo nmcli connection up GreenTree

# 查看当前 IP
ip -4 addr show wlan0
```

**DNS 问题**: 若 `apk` 报 "DNS: transient error", 检查 `/etc/resolv.conf`:
```bash
# resolv.conf 若是 symlink 到 127.0.0.53 且 systemd-resolved 未运行会 REFUSED
ls -l /etc/resolv.conf
sudo rm -f /etc/resolv.conf
echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf
echo "nameserver 223.5.5.5" | sudo tee -a /etc/resolv.conf
```

## 6. 服务器脚本重新部署 (rootfs 被刷后必做)

**关键教训**: 跨设备部署 tar 包**必须** `--owner=root --group=root`, 否则主机 uid 污染设备 /etc, 导致 sudo 永久拒绝 (`/etc must be owned by root`)。

### 6.1 打包 (主机侧)

```bash
cd /home/lyl/Documents/system/XiaoMiNote3/refs/server-scripts
tar --owner=root --group=root -czf /tmp/server-scripts-fixed.tar.gz \
    usr-local-bin/ etc-systemd/ etc-systemd-journald.conf.d/ \
    etc-ssh-sshd_config.d/ etc-sysctl.d/ etc-profile.d/
```

### 6.2 部署 (设备侧)

```bash
# scp 推送
sshpass -p 'DEVICE_PASS_PLACEHOLDER' scp /tmp/server-scripts-fixed.tar.gz user@172.16.42.1:/tmp/

# 设备上解压 (必须 --no-same-owner 或打包时已 --owner=root)
ssh user@172.16.42.1 'echo DEVICE_PASS_PLACEHOLDER | sudo -S sh -c "
    cd /
    tar --no-same-owner -xzf /tmp/server-scripts-fixed.tar.gz
    chmod +x /usr/local/bin/*.sh
    systemctl daemon-reload
    systemctl enable --now health-check.timer temp-monitor.timer net-monitor.timer \
        disk-io-monitor.timer fake-rtc-save.timer battery-care.timer \
        apk-update-check.timer fsck-check.timer config-backup.timer
    rm /tmp/server-scripts-fixed.tar.gz
"'
```

### 6.3 验证

```bash
ssh user@172.16.42.1 'systemctl list-timers --all | head -15'
# 应看到 9 个 timer (health-check/temp-monitor/net-monitor/disk-io-monitor/fake-rtc-save/battery-care/apk-update-check/fsck-check/config-backup)
```

## 8. deploy.sh 参数速查

| 参数 | 用途 | 前置条件 | 是否丢失设备配置 |
|---|---|---|---|
| `--update-uuid` | 从 rootfs 镜像更新 boot.img cmdline UUID | pmbootstrap export 完成 | 否 |
| `--flash-rootfs` | fastboot flash userdata (刷 rootfs) | 设备在 fastboot | **是** (userdata 被覆盖) |
| `--boot-temp` | fastboot boot (临时启动, 不持久化) | 设备在 fastboot | 否 |
| `--flash-boot` | dd 写入 boot 分区 (持久化) | 设备已启动, SSH 可达 | 否 |
| `--verify` | 验证 SSH + cpufreq | 设备已启动 | 否 |
| `--all` | 一键完整部署 (update-uuid + flash-rootfs + boot-temp + verify) | 设备在 fastboot | **是** |
| `--persist` | 持久化 boot (flash-boot + verify) | 设备已启动 | 否 |

## 9. 权威 UUID (恢复基准, 2026-07-02 实测)

```
boot 子分区 (loop0p1, ext2, LABEL=pmOS_boot):
  UUID=8df5edb6-14ae-4951-b1d4-777b1e8b8969

root 子分区 (loop0p2, ext4, LABEL=pmOS_root):
  UUID=d0cfb99c-3fb7-4461-abba-434e67f67807
```

boot.img cmdline 中 `pmos_boot_uuid` 和 `pmos_root_uuid` 必须匹配以上值, 否则 rootfs 挂载失败。`pmbootstrap install` 后 UUID 会变, 必须用 `deploy.sh --update-uuid` 同步。
